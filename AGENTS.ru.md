# Инструкции для агентов, работающих с Core

Этот файл — для агентов, которые **редактируют сам Core** (спецификации DocHub). Инструкции для агентов, работающих с **хабом**, — в [rules/agents](rules/agents.ru.md) и в шаблоне [hub-AGENTS](templates/hub-AGENTS.ru.md).

## Правила

1. **Не выдумывать.** Описывать только согласованное или следующее из источников. Нет информации — так и написать; несогласованное помечать **«предложение»**, нерешённое — **«открытый вопрос»** и вносить в [список](concepts/overview.ru.md#открытые-вопросы).
2. **Согласованность.** Одно поле или понятие называется одинаково везде. При изменении поля обновить вместе: спецификацию (`specifications/`), схему (`schemas/`), примеры (`examples/`), шаблоны (`templates/`).
3. **Термины** — из [glossary](concepts/glossary.ru.md). Новый термин сначала добавить туда.
4. **Язык.** Новые документы — на русском, с суффиксом `.ru.md`. Английские версии — см. [translation](rules/translation.ru.md).
5. **Имена** — по [naming](rules/naming.ru.md).
6. **Ссылки** — относительные Markdown-ссылки, чтобы они работали в Obsidian, на GitHub и в Web.
7. **Frontmatter** документа Core: `type: doc`, `lang`, `status` (`draft` | `actual` | `outdated`), `updated` (`YYYY-MM-DD`).
8. **Границы Core.** Core описывает концепцию и файловый протокол, а не реализации: сетевой API и устройство приложений сюда не входят. Команды реализаций описаны только в [cli-contract](specifications/cli-contract.ru.md): это пример реализации, а не часть протокола. Остальные документы называют операции («запись в wiki», «выгрузка docs»), а не команды. Хаб — источник истины только для wiki; внешнюю документацию (docs) он не правит и в git не хранит. Как проекту вести задачи, Core не требует: функция [board](specifications/features/board.ru.md) необязательна.
