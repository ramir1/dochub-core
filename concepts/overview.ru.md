# Обзор DocHub

## Проблема

Над проектами всё чаще работают несколько ИИ-агентов: разные инструменты (Claude Code, Codex и др.) в одном репозитории, параллельные сессии на разных зонах (backend, frontend, тесты), агенты разных людей и машин, агенты соседних проектов, которые используют общий контракт.

У этих агентов нет ничего общего, кроме файлов:

- **нет канала** — агент не может спросить другого агента или сообщить ему «я поменял формат, проверь клиент»; это делает человек, пересказывая;
- **нет общей памяти** — договорённости остаются в сессии и памяти одного инструмента, другой инструмент или следующая сессия о них не знает;
- **нет информирования** — агент не знает, что изменилось в документации с его последней сессии;
- **нет координации** — два агента могут одновременно взяться за одно и то же;
- **нет общего места чтения** — документация разных проектов разбросана по клонам на разных машинах, её неудобно читать и искать вместе с обсуждениями.

## Суть

**DocHub — единое место документации проектов и слой координации агентов вокруг неё.** У проекта есть своя документация — [wiki](../specifications/wiki.ru.md), для которой хаб источник истины, и подключённая внешняя — [docs](../specifications/docs-sources.ru.md), только для чтения. Вокруг них хаб даёт агентам общий канал и общую память (обсуждения), информирование об изменениях и координацию (отметки работы), см. [features](features.ru.md).

## Принципы

- **Два вида документации.** Wiki живёт в хабе, правится человеком в Obsidian, агентом — через реализацию или по скилу. Docs живёт в своём репозитории, хаб выгружает её для чтения и в git не хранит. Что куда класть — [wiki](../specifications/wiki.ru.md#что-класть-в-wiki).
- **Требования — только к wiki.** К своей документации хаб предъявляет требования; к внешней — нет. Как вести задачи, DocHub не задаёт.
- **Только нужное.** Функции подключаются к проекту по выбору.
- **Markdown + Git.** Данные хаба — Markdown-файлы с frontmatter и служебные YAML-файлы в git-репозитории хаба. Их можно читать без DocHub, а Markdown — и в Obsidian.
- **Запись без ручных конфликтов.** Отметки агентов разложены так, что файл меняет только его автор. Запись в обсуждение при столкновении повторяется поверх свежей версии. На wiki действуют обычные конфликты git, см. [wiki](../specifications/wiki.ru.md#одновременные-правки).
- **Протокол и реализации.** DocHub — это концепция и файловый протокол; утилиты и Web — надстройки, которые можно переписать. См. [levels](levels.ru.md).
- **Запись по уровню.** Без утилиты агент пишет файлы сам по [скилу](../skills/dochub/SKILL.md); с утилитой — только через неё. Люди читают и пишут в Obsidian.
- **Идентичность — у агента, права — у хаба.** Имя агента задаётся на машине — в локальном манифесте или окружении, а не в git репозитория; права выдаёт конфигурация хаба.
- **Честность.** Неизвестное помечается как неизвестное, см. [writing](../rules/writing.ru.md).

## Открытые вопросы

1. **Правила проектов для внешних агентов.** Как внешний агент узнаёт правила вне документации (например, `AGENTS.md` в корне репозитория) — отложено.
2. **Общие знания вне проектов.** Предложение: оформлять их отдельным проектом с wiki.
3. **Поиск по обсуждениям** (общая память) без индексатора — только простой текстовый поиск.

Аутентификация, закрытая часть wiki и доставка docs агентам без доступа к репозиторию — вопросы реализаций уровня 3, см. [levels](levels.ru.md#уровень-3-сервис).
