# Архитектура

Слои и уровни работы — [levels](levels.ru.md).

## Составные части

| Часть | Что это | Где описано |
|---|---|---|
| **Core** | Этот репозиторий: описание, спецификации, схемы, правила | [README](../README.ru.md) |
| **Репозитории проектов** | Код и внешняя документация. Хаб их только читает | [docs-sources](../specifications/docs-sources.ru.md) |
| **Хаб** | Git-репозиторий: конфигурация, wiki проектов и данные функций. Он же Obsidian-vault | [hub-storage](../specifications/hub-storage.ru.md) |
| **Wiki** | `projects/<id>/wiki/` — своя документация проекта, хаб источник истины | [wiki](../specifications/wiki.ru.md) |
| **Docs** | `projects/<id>/docs/<папка>/` — выгрузка внешней документации, только чтение, не в git | [docs-sources](../specifications/docs-sources.ru.md) |
| **Функции** | Обсуждения, изменения, отметки работы | [features](features.ru.md) |
| **Реализации** | Эталонная утилита, Web, собственные инструменты | [levels](levels.ru.md), [protocol](../specifications/protocol.ru.md) |
| **Агенты** | ИИ-агенты и люди с именами; работают на разных машинах | [access](../specifications/access.ru.md) |

## Схема

```
  Машина 1                                  Машина 2
  ┌──────────────────────────────┐          ┌──────────────────────────────┐
  │ portal/ (репозиторий)        │          │ mobile/ (репозиторий)        │
  │   docs/                      │          │   .doc-hub.json              │
  │   .doc-hub.json              │          │                              │
  │ агенты: backend (Claude),    │          │ агент: mobile-dev            │
  │         frontend (Codex)     │          │                              │
  │ хаб/ (клон) ◄ агент/Obsidian │          │ хаб/ (клон) ◄ агент          │
  │   projects/portal/docs/tech/ │          │                              │
  │     ◄─ выгрузка из portal/   │          │                              │
  └──────────────┬───────────────┘          └──────────────┬───────────────┘
                 │ git pull / push                         │ git pull / push
                 ▼                                         ▼
            ┌────────────────── origin хаба ──────────────────┐
            │ .doc-hub/config.yaml  — проекты, агенты, права  │
            │ projects/portal/wiki/ — своя документация       │
            │ projects/portal/discussions/ claims/ changes/   │
            └─────────────────────────────────────────────────┘
  projects/*/docs/ на каждой машине свои и в origin хаба не попадают.
```

## Потоки

**Wiki.** Хранится в хабе. Человек правит в Obsidian, агент — через реализацию или по скилу; писать может владелец зоны.

**Docs.** Явная операция выгрузки копирует документацию с зафиксированного коммита локальной ветки клона (путь — в `config.local.yaml` хаба) в `projects/<id>/docs/<папка>/` с паспортом. В git хаба выгрузка не попадает.

**Чтение документации.** Wiki — из клона хаба; docs — из выгрузки, иначе из коммита в клоне репозитория. Реализация показывает агенту только разрешённые пути.

**Правка внешней документации.** Только в её репозитории, обычным образом. Хаб в этом не участвует.

**Запись в функции.** Агент работает в своём репозитории и пишет в хаб через реализацию или сам по скилу: файлы создаются в клоне хаба, коммитятся и отправляются в origin. Отметки работы и просмотра пишет только их автор, поэтому они не конфликтуют. Обсуждения дописывают разные агенты: столкновения разрешаются по [hub-storage](../specifications/hub-storage.ru.md#столкновения-записи).

**Синхронизация.** Перед чтением данных хаба — `git pull`, после записи — `commit` + `push`. Люди в Obsidian — плагином Git.

## Что вне Core

Сервис с API, Web, индексатор и поиск, развёртывание (Docker и т. п.), аутентификация — это устройство реализаций, см. [levels](levels.ru.md).
