# Уровни работы

## Слои

| Слой | Что это | Где |
|---|---|---|
| Концепция | Понятия: wiki, docs, зоны, агенты, функции | `concepts/` |
| Протокол | Обязательные правила совместимости | [protocol](../specifications/protocol.ru.md), `specifications/`, `schemas/` |
| Реализации | CLI, Web, MCP, собственные инструменты | Отдельные репозитории |

DocHub — это концепция и протокол. CLI и Web — надстройки: их можно переписать под протокол или написать свои. `doc-hub` — эталонная реализация, а не обязательная часть.

Протокол один — файловый. Сетевой протокол концепция не описывает: сервис с API — это реализация, и его API принадлежит ей.

## Уровни

Уровень определяется тем, что стоит между агентом и файлами хаба.

| Уровень | Что есть | Как работает агент | Что контролирует |
|---|---|---|---|
| 1. Ядро | Core и файлы хаба | Сам читает и пишет файлы по [скилу](../skills/dochub/SKILL.md) | Только инструкции |
| 2. Утилита | Плюс реализация на машине агента (`doc-hub`) | Через команды | Утилита проверяет права, форматы, статусы |
| 3. Сервис | Реализация с собственным API поверх хаба | Через клиент этой реализации, файлов на машине нет | Реализация |

Человек на уровнях 1 и 2 работает с файлами напрямую в Obsidian.

### Уровень 1. Ядро

Для старта нужны только Core и папка хаба. Агент получает прямой доступ к файлам и работает по скилу.

Скил объясняет, а не запрещает: права, зоны и форматы держатся на дисциплине агента. Возможны ошибки в полях, времени и `uid`, пропущенные шаги. Проверить результат можно любой реализацией `validate`.

### Уровень 2. Утилита

Реализация убирает ручные шаги: сама ставит `uid` и время, проверяет права и переходы статусов, синхронизирует хаб. Агент работает только через неё.

Это защита от ошибок, а не от намеренного обхода: файлы хаба лежат на машине агента, и доступ к ним технически остаётся.

### Уровень 3. Сервис

Файлы хаба лежат только на сервере, агент получает то, что отдаст сервис. Только здесь возможны настоящая проверка агента и прав, закрытая часть wiki и доставка docs агентам без доступа к репозиторию.

Как это устроено, Core не описывает. Сервис хранит данные по файловому протоколу, поэтому совместим с остальными реализациями на уровне хаба.

## Хранение хаба

Это не уровень, а способ, общий для уровней 1 и 2:

| Способ | Что это | Границы |
|---|---|---|
| Папка | Хаб на одной машине, без origin | Одна машина |
| Git-сервер | Репозиторий хаба на сервере, на машинах — клоны | Несколько машин; клон раскрывает всю wiki |

Docker не отдельный уровень: смонтированная папка или git в контейнере — это хранение на уровнях 1 и 2, API в контейнере — уровень 3.

## Переход между уровнями

Формат файлов на всех уровнях один, поэтому переход не требует переноса данных. С уровня 1 на уровень 2 достаточно установить реализацию. На уровень 3 — развернуть сервис поверх того же хаба.
