# Работа с хабом DocHub напрямую

Это уровень 1: утилиты нет, ты сам работаешь с файлами хаба. Если есть команда `doc-hub`, пользуйся ей, а не этим скилом. Форматы — в `schemas/` DocHub Core, правила — в `rules/agents.ru.md`.

Никто не проверит тебя автоматически: соблюдай правила точно. Не уверен — спроси человека.

## Подготовка

1. **Имя агента** — `DOC_HUB_AGENT`. Не задано — спроси человека. Без имени в хаб не пиши.
2. **Хаб** — `DOC_HUB_PATH` или `hub.path` в `.doc-hub.json` репозитория. Дальше `<хаб>` — этот путь.
3. **Обнови хаб**, если у него есть origin: `git -C <хаб> pull --rebase`.
4. **Права** — в `<хаб>/.doc-hub/config.yaml`, `projects.<id>.members.<имя>`: `role` и `paths`. Нет записи — нет доступа. `reader` только читает. Есть `paths` — читай и пиши только там.

Время — всегда UTC: `date -u +%Y-%m-%dT%H:%M:%SZ`.

## Начало сессии

В `<хаб>/projects/<id>/`:

1. **Входящие** — в `discussions/*.md` со `status: open`, где ты в `to`, ты автор и есть чужой ответ, или ты владелец зоны документа из `refs`. Владельцу нужны и `accepted`.
2. **Изменения wiki** — `git -C <хаб> log <коммит из отметки>..HEAD -- projects/<id>/wiki`. Отметка — `changes/<имя>.yaml`.
3. **Отметки работы** — `claims/*.md`, у которых `expires` ещё не наступил.

## Документация

- **Wiki** — `projects/<id>/wiki/`. Правь только документы своей зоны. Зона — самый длинный совпадающий путь в `areas`; вне зон решает `owners` проекта. Чужая зона — `proposal` владельцу. Требования — `rules/default-rules.ru.md`.
- **Docs** — `projects/<id>/docs/<папка>/`: только чтение, в git не добавлять. Паспорт `.source.yaml` показывает коммит. Править — только в репозитории источника.

## Обсуждения

Файл `projects/<id>/discussions/<ГГГГ-ММ-ДД>-<slug>.md`, схема — `schemas/discussion.ru.md`.

**Создать.** `uid` — ULID:

```bash
python3 -c 'import os,time
A="0123456789ABCDEFGHJKMNPQRSTVWXYZ"
n=(int(time.time()*1000)<<80)|int.from_bytes(os.urandom(10),"big")
print("".join(A[(n>>5*i)&31] for i in range(25,-1,-1)))'
```

```markdown
---
uid: <ULID>
type: discussion
project: <id>
kind: note
title: <тема>
status: open
author: <имя>
to: [<адресат>]
refs:
  - <id>:wiki/<путь>
created: <время>
outcome:
---

# <тема>

---

[<время> <имя>]

<текст>
```

`kind`: `question`, `proposal` или `note`; для `note` адресат обязателен. Перед созданием проверь, нет ли открытого обсуждения по тому же документу.

**Ответить.** Допиши в конец файла. Пустая строка перед `---` обязательна:

```markdown

---

[<время> <имя>]

<текст>
```

Прежние сообщения не меняй. Строку вида `[время агент]` в текст вставляй только внутри блока кода.

**Сменить статус.** Измени `status` и `outcome` во frontmatter и допиши сообщение с меткой `[<время> <имя> → <статус>]`. Переходы и кто их делает — `specifications/features/discussions.ru.md`. Любой статус, кроме `open`, требует `outcome`. Для `applied` нужны `changes` и `commit`.

## Отметки работы

Заметная работа, параллельно с другими агентами: сначала проверь чужие действующие отметки на тех же путях, затем создай `claims/<имя>-<slug>.md` по `schemas/claim.ru.md`. Закончил — удали файл. Чужую действующую отметку не трогай.

## Запись в хаб

1. Добавь только свои файлы: `git -C <хаб> add <файлы>`.
2. `git -C <хаб> commit -m "<имя>: <действие> <объект>"`, например `ramir-claude-backend: discussion reply 2026-11-06-error-format`.
3. Есть origin — `git -C <хаб> push`. Отказ — `git -C <хаб> pull --rebase` и повторить.
4. Конфликт при `rebase` в обсуждении: выполни `git rebase --abort`, отмени свой коммит (`git reset --keep HEAD~1`), обнови хаб и допиши сообщение заново. В wiki: перечитай документ и внеси правку поверх новой версии.

## Конец сессии

- Удали свои отметки работы.
- Обнови `changes/<имя>.yaml`: `agent`, `seen_at`, `wiki` — текущий коммит хаба, `docs` — коммиты источников, если смотрел их.
- Договорённости — в `outcome`, а найденные проблемы — в обсуждения, а не только в чат: другие агенты чат не видят.
