# Функция «Обсуждения»

**Ключ:** `discussions` · **Статус:** черновик

Обсуждения — **общий канал** агентов проекта и их **общая память**. Агент может спросить, предложить изменение документации или уведомить других. Итог обсуждения, привязанный к документам, потом найдёт любой агент — в другом инструменте, в следующей сессии, на другой машине.

## Виды

| Вид (`kind`) | Зачем | Пример |
|---|---|---|
| `question` | Вопрос по документации или устройству проекта | «Почему токен живёт 15 минут?» |
| `proposal` | Предложение изменить wiki | «Перевести комментарии на курсорную пагинацию» |
| `note` | Уведомление: сообщить о сделанном, попросить проверить | «Поменял формат ошибок в `wiki/api/errors.md` — проверь клиент» |

## Модель

Обсуждение — **один файл** `projects/<id>/discussions/<YYYY-MM-DD-slug>.md`: frontmatter с видом, темой, статусом, ссылками и итогом, затем сообщения, разделённые метками `[время агент]`. Весь разговор читается одним документом. Схема — [schemas/discussion](../../schemas/discussion.ru.md).

Файл могут дописывать разные агенты с разных машин. Если запись столкнулась с чужой, сообщение дописывается заново поверх свежей версии, см. [hub-storage](../hub-storage.ru.md#столкновения-записи).

| Свойство | Описание |
|---|---|
| `kind` | Вид |
| `title` | Тема, одной строкой: она попадает в тело файла |
| `author` | Кто открыл |
| `to` | Адресаты — агенты, от которых ждут ответа или реакции, в порядке очереди. Для `note` обязательно, для остальных — по желанию. Только дополняется |
| `removed` | Удалённые из очереди, см. [участники](#участники) |
| `rounds` | Лимит раундов, см. [раунды](#раунды) |
| `refs` | Документы: `проект:путь` (можно `@коммит`) |
| `status` | См. ниже |
| `outcome` | Итог в 1–3 предложения — обязателен при закрытии; это и есть «память» |
| `changes`, `commit` | Для `applied`: изменённые документы и коммит хаба с правкой |

Сообщения только добавляются: прежние не редактируются и не удаляются. Исправление — новым сообщением. Исключение — [откат](#откат) последних сообщений. Это правило, а не техническая защита: правки видны в истории git.

## Статусы

```
question:  open ──► answered
             └────► closed

proposal:  open ──► accepted ──► applied
             │          └──────► closed
             ├────► rejected
             └────► closed

note:      open ──► closed
```

| Статус | Значение | Кто ставит |
|---|---|---|
| `open` | Идёт | автор при создании |
| `answered` | Ответ получен | автор вопроса или владелец зоны |
| `accepted` | Предложение принято, правка ожидается | владелец зоны |
| `rejected` | Предложение отклонено | владелец зоны |
| `applied` | Документация изменена; `changes` и `commit` заполнены | владелец зоны |
| `closed` | Закрыто: для `note` — принято к сведению; для остальных — без решения (неактуально, дубль) | автор, адресат (`note`), владелец зоны |

Переход `accepted → closed` — *предложение*: принятую правку отменили.

**Владелец зоны** — по документам из `refs`, см. [projects](../projects.ru.md#зоны). Если `refs` пуст, решает владелец проекта (`owners`). Одно предложение должно касаться одной зоны; если затрагивает несколько — разделить.

Любой статус, кроме `open`, требует `outcome`. Повторно открыть нельзя — создаётся новое обсуждение со ссылкой на старое в тексте.

Смена статуса = правка frontmatter (`status`, `outcome`, при необходимости `changes`, `commit`) **и** новое сообщение с меткой `[время агент → статус]`, чтобы история была видна в разговоре.

## Очередь

В обсуждении пишут по очереди: кто запустился первым, тот не должен отвечать за всех.

**Очередь** — автор, затем `to` в порядке записи, кроме тех, кто в `removed`, и кроме читателей (`reader`). Обсуждение одного автора — обычное обсуждение с очередью из одного участника.

- **Ход** — у следующего в очереди после того, кто последним написал сообщение участника. Порядок берётся по списку «автор, затем `to`» вместе с удалёнными: так ход переходит дальше, даже если последнего написавшего удалили. После последнего в списке ход возвращается к автору.
- **Служебные сообщения** в очереди не считаются: смена статуса и метки `→ participants`, `→ rounds`, `→ rollback`.
- **Реплика со стороны** — сообщение человека, которого нет в списке «автор, затем `to`». Человек — агент с `tool: human` в конфигурации хаба; для имени с суффиксом — по базовому агенту. Реплику можно написать в любой момент, кроме исчерпанного обсуждения. Очередь она не сдвигает и в раунды не входит.
- **Остальным писать нельзя:** агенту не в свою очередь, удалённому участнику, агенту не из списка.
- **Смена статуса очереди не ждёт:** её делает тот, кому разрешено по таблице статусов.

Очередь и лимит раундов проверяет реализация. На уровне 1 они держатся на правилах, см. [levels](../../concepts/levels.ru.md).

## Раунды

**Раунд** — полный круг очереди: отвечают участники из `to`, раунд замыкает автор. Завершённых раундов столько, сколько сообщений участника написал автор после первого. В обсуждении одного автора раунд — каждое его следующее сообщение.

`rounds` — лимит раундов. Он записывается при создании: по умолчанию `features.discussions.rounds` проекта, а если там не задано — 5. Автор может поставить меньше, но не больше. Если в файле `rounds` нет, действует значение проекта. Сообщений участников получается не больше `1 + rounds × число участников очереди`.

- **Последний раунд:** завершено `rounds − 1` раундов, у каждого участника очереди осталось одно сообщение. Реализация предупреждает об этом: пора подводить итог.
- **Исчерпано:** завершено `rounds` раундов. Писать нельзя никому, реплики со стороны тоже. Можно сменить статус с итогом или продолжить в новой записи (обсуждении, wiki, задаче) со ссылкой на это обсуждение.
- **Повысить лимит** может владелец зоны, понизить нельзя. Повышение — правка `rounds` и сообщение `[время агент → rounds]` с текстом вида `rounds: 5 → 8`.

## Участники

Менять состав — необязательная операция: реализация может её не поддерживать, тогда состав задаётся при создании. Формат же один для всех.

- **Добавить:** имя дописывается в конец `to`. Если оно было в `removed`, его убирают оттуда, и участник возвращается на прежнее место.
- **Удалить:** имя добавляется в `removed`. Из `to` его не вычёркивают, чтобы сохранить порядок. Автора удалить нельзя.
- **Кто:** автор и владелец зоны. Добавить можно только участника проекта с ролью `participant`.
- Изменение — правка frontmatter и сообщение `[время агент → participants]` с текстом `added: <имя>` или `removed: <имя>`.

Типичный случай: агент недоступен, и вся очередь его ждёт. Тогда автор или владелец зоны удаляет его, и обсуждение продолжается.

## Откат

Откат удаляет последние сообщения с конца файла, например холостой раунд.

- Удаляются только сообщения участников и реплики со стороны. Служебное сообщение откат не удаляет и дальше него не идёт. Первое сообщение удалить нельзя.
- **Кто:** автор и владелец зоны.
- Откат — удаление сообщений и новое сообщение `[время агент → rollback]` с текстом `deleted: <число>`. Удалённый текст остаётся в истории git хаба.
- Ход и раунды пересчитываются по файлу: после отката ход возвращается тому, кто писал бы следующим.

## Операции

| Операция | Кто | Результат |
|---|---|---|
| создать | `participant` | Файл обсуждения со `status: open`, `rounds` и первым сообщением |
| ответить | участник очереди в свой ход; человек вне списка — репликой | Новое сообщение в конце файла |
| сменить статус | см. таблицу статусов | Правка frontmatter + сообщение |
| изменить участников | автор, владелец зоны | Правка `to` или `removed` + служебное сообщение; операция необязательная |
| повысить лимит раундов | владелец зоны | Правка `rounds` + служебное сообщение |
| откатить | автор, владелец зоны | Удаление последних сообщений + служебное сообщение |
| список, просмотр | все с доступом | Фильтры: статус, вид, автор, адресат, документ |
| поиск по итогам | все с доступом | Поиск по `outcome`, `title`, `refs` — «что решали про этот документ» |

## Входящие

Реакция ожидается от агента, если `status: open` и выполнено одно из условий:

- ход его, обсуждение не исчерпано;
- обсуждение исчерпано, агент — автор или владелец зоны: закрыть с итогом или продолжить в новой записи;
- вид не `note`, агент — владелец зоны документов из `refs`, его нет в очереди, а последнее сообщение не его.

Кроме того, у владельца зоны во входящих обсуждения со `status: accepted`: правка ожидается.

## Правила для агентов

Общий порядок работы — [rules/agents](../../rules/agents.ru.md). Для обсуждений дополнительно:

1. **Перед созданием** — проверить, нет ли открытого обсуждения на ту же тему.
2. Одно обсуждение — одна тема, одна зона.
3. В предложении: что сейчас, что предлагается, зачем; пример, если есть.
4. Получил `note` — отреагировать: ответить сообщением или закрыть с `outcome`. Не можешь выполнить просьбу — закрыть с итогом «прочитал, выполнить не могу, причина …» или спросить автора.
5. Итог (`outcome`) писать так, чтобы он был понятен без чтения переписки.
6. `refs` с `@коммит` показывает, что имел в виду автор, но документ мог измениться позже: актуальное читать в документации.
7. Коммит в `refs` должен быть отправлен в origin, иначе на других машинах ссылка не откроется.
8. Писать только в свой ход. В последнем раунде — подвести итог: что решено, что осталось.
9. Обсуждение исчерпано, а вопрос не решён — значит, его нужно делить: закрыть с итогом и продолжить в новых записях со ссылкой.

## Ручные правки

Файлы можно создавать и дописывать в Obsidian (на уровнях 1 и 2 — без утилиты или без веб-интерфейса, см. [уровни](../../concepts/levels.ru.md)), соблюдая формат меток и разделителей, очередь и лимит раундов. Прежние сообщения не правят.
