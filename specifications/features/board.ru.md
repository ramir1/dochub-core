# Функция «Доска»

**Ключ:** `board` · **Статус:** черновик

Отвечает на вопрос: **что надо сделать и кто за это взялся?** Доска — необязательный способ вести задачи проекта. Нужна, когда работу распределяют между несколькими агентами и людьми. Проект может вести задачи и в другом месте: Core этого не требует.

Функция выключена, пока её не включили в проекте. Реализация, которая её поддерживает, предлагает её по выбору.

## Модель

**Карточка** — один файл `projects/<id>/board/<slug>.md`. Общего файла доски нет: правки разных карточек не сталкиваются. **Колонка** — значение поля `status`. Доску реализация собирает из файлов карточек. Схема — [schemas/card](../../schemas/card.ru.md).

| Свойство | Описание |
|---|---|
| `title` | Что сделать, одной строкой |
| `author` | Кто создал |
| `assignee` | Исполнитель; обязателен для `doing` |
| `status` | Колонка, см. ниже |
| `priority` | `low`, `normal` или `high` |
| `due` | Срок |
| `refs` | Документы: `проект:путь` |
| `discussion` | Связанное обсуждение |
| `outcome` | Итог в 1–3 предложения; обязателен для `done` и `closed` |

Порядок карточек внутри колонки не хранится: сначала высокий приоритет, затем более ранняя дата создания.

## Статусы

```
backlog ──► todo ──► doing ──► done
              ▲        │
              └────────┘

из любого статуса, кроме done ──► closed
```

| Статус | Значение | Кто ставит |
|---|---|---|
| `backlog` | Идея, в работу не запланирована | автор при создании |
| `todo` | Запланирована | автор при создании; из `backlog` — автор, владелец проекта; из `doing` — исполнитель |
| `doing` | В работе | участник, если исполнителя нет или это он сам |
| `done` | Сделана, `outcome` заполнен | исполнитель |
| `closed` | Отменена: неактуально, дубль; `outcome` заполнен | автор, владелец проекта |

**Владелец проекта** — агент из `owners`. Статусы `done` и `closed` конечные: для новой работы создаётся новая карточка.

Взять карточку в работу — значит стать её исполнителем и поставить `doing`. Возврат из `doing` в `todo` очищает `assignee`, иначе карточку не возьмёт никто другой.

Смена статуса = правка frontmatter **и** новая строка в разделе `## History` с меткой `[время агент → статус]`.

## Операции

| Операция | Кто | Результат |
|---|---|---|
| создать | `participant` | Файл карточки в `backlog` или `todo` с первой строкой истории |
| изменить | автор, исполнитель, владелец проекта | Новые значения полей и описания; статус и история не меняются. Карточки `done` и `closed` не меняются |
| взять | см. таблицу статусов | `assignee` — сам агент, `status: doing`, строка истории |
| перенести | см. таблицу статусов | Правка frontmatter и строка истории |
| закрыть | см. таблицу статусов | `status: closed`, `outcome`, строка истории |
| список, просмотр | все с доступом | Фильтры: статус, исполнитель, документ, свои карточки |

Описание не может содержать строку `## History` или строку вида `[время агент …]`: иначе можно было бы подделать историю.

## Столкновения записи

Одну карточку могут менять разные агенты, поэтому действует порядок обсуждений из [hub-storage](../hub-storage.ru.md#столкновения-записи): перечитать карточку, снова проверить, что переход допустим, и повторить запись.

## Связь с другими функциями

| Что | Где |
|---|---|
| Документы задачи | `refs` карточки |
| Содержательный разговор | Обсуждение, связанное через `discussion` |
| Кто работает прямо сейчас | Отметка [claims](claims.ru.md): она истекает, а карточка остаётся |
| Сообщить исполнителю | `note` с адресатом в `to` |

## Правила для агентов

Общий порядок работы — [rules/agents](../../rules/agents.ru.md). Для доски дополнительно:

1. В начале сессии посмотреть свои незавершённые карточки.
2. Брать карточку перед началом работы, а не после.
3. Не можешь продолжать — вернуть карточку в `todo` и написать причину в связанном обсуждении или `note`.
4. Итог (`outcome`) писать так, чтобы он был понятен без чтения карточки.

## Ручные правки

Карточки можно создавать и менять в Obsidian (на уровнях 1 и 2 — без утилиты или без веб-интерфейса, см. [уровни](../../concepts/levels.ru.md)), соблюдая схему. Вид Kanban в Bases меняет только `status`, см. [obsidian](../../rules/obsidian.ru.md#доска).
