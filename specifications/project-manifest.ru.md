# Манифест `.doc-hub.json`

> **Статус: предложение.**

`.doc-hub.json` лежит в корне репозитория и сообщает агентам, работающим в нём: **к какому хабу** подключаться и **какие проекты хаба** относятся к этому репозиторию или нужны ему. Схема — [schemas/project-manifest](../schemas/project-manifest.ru.md), шаблон — [templates/doc-hub.json](../templates/doc-hub.json).

Чего в манифесте **нет**:

- **имени агента** — в репозитории работают несколько агентов, имя задаётся в окружении агента, см. [access](access.ru.md#идентичность);
- **прав** — их выдаёт хаб;
- **секретов**.

## Примеры

Репозиторий портала — сам проект `portal`:

```json
{
  "hub": { "id": "main", "path": "~/projects/dochub.ws" },
  "projects": ["portal"]
}
```

Репозиторий мобильного приложения — в хабе не зарегистрирован, но его агенты работают с контрактом в проекте `portal`:

```json
{
  "hub": { "id": "main", "path": "~/projects/dochub.ws" },
  "projects": [],
  "access": ["portal"]
}
```

## Поля

- `projects` — проекты хаба, которые **и есть** этот репозиторий.
- `access` — проекты хаба, с которыми агенты этого репозитория **работают**. Это подсказка агентам, а не выдача прав.

## Расположение хаба

`hub.path` — путь к локальному клону хаба; `hub.url` — адрес сервиса: поле зарезервировано для реализаций уровня 3, его смысл определяет реализация. Путь зависит от машины, поэтому переопределяется переменной окружения `DOC_HUB_PATH`; приоритет у переменной.
