# Манифест `.doc-hub.json`

`.doc-hub.json` лежит в корне репозитория и сообщает агентам, работающим в нём, **к каким хабам** подключаться, а для каждого хаба — **какие его проекты** относятся к этому репозиторию или нужны ему и **какое имя агента** использовать по умолчанию.

Манифест **свой на каждой машине и не хранится в git**: в нём пути к клонам хабов и имена агентов. Файл добавляют в `.gitignore` репозитория. Схема — [schemas/project-manifest](../schemas/project-manifest.ru.md), шаблон — [templates/doc-hub.json](../templates/doc-hub.json).

Чего в манифесте **нет**:

- **прав** — их выдаёт хаб;
- **секретов**.

## Примеры

Репозиторий портала — сам проект `portal`:

```json
{
  "hubs": {
    "main": { "path": "~/projects/hub", "projects": ["portal"], "agent": "portal" }
  }
}
```

Репозиторий, который в хабе не зарегистрирован, но работает с его проектом, — `projects: []` и `access: ["portal"]`, см. [contract-zone](../examples/contract-zone.ru.md#репозиторий-мобильного-приложения).

## Несколько хабов

Параметры разделены по хабам: ключ раздела — `hub.id` из конфигурации хаба. Репозиторий может работать с несколькими хабами:

```json
{
  "hubs": {
    "main": { "path": "~/projects/hub", "projects": ["portal"], "agent": "portal" },
    "work": { "path": "~/work/hub", "projects": [], "access": ["api"], "agent": "portal-client" }
  }
}
```

Хаб выбирается по порядку из [протокола](protocol.ru.md#определение-контекста), по умолчанию — первый раздел. Проекты и имя агента берутся из раздела выбранного хаба.

## Имя агента

`agent` — имя по умолчанию в этом хабе. Другому агенту в этом репозитории задают суффикс или полное имя, см. [access](access.ru.md#идентичность).

## Расположение хаба

`path` — путь к локальному клону хаба; `url` — адрес сервиса: поле зарезервировано для реализаций уровня 3, его смысл определяет реализация. Путь зависит от машины, поэтому переопределяется переменной окружения `DOC_HUB_PATH`; приоритет у переменной.
