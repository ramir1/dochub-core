# Манифест `.doc-hub.json`

> **Статус: предложение.**

`.doc-hub.json` лежит в корне репозитория и сообщает агентам, работающим в нём: **к какому хабу** подключаться, **какие проекты хаба** относятся к этому репозиторию или нужны ему и **какое имя агента** использовать по умолчанию.

Манифест **свой на каждой машине и не хранится в git**: в нём путь к клону хаба и имя агента. Файл добавляют в `.gitignore` репозитория. Схема — [schemas/project-manifest](../schemas/project-manifest.ru.md), шаблон — [templates/doc-hub.json](../templates/doc-hub.json).

Чего в манифесте **нет**:

- **прав** — их выдаёт хаб;
- **секретов**.

## Примеры

Репозиторий портала — сам проект `portal`:

```json
{
  "hub": { "id": "main", "path": "~/projects/hub" },
  "projects": ["portal"],
  "agent": "portal"
}
```

Репозиторий, который в хабе не зарегистрирован, но работает с его проектом, — `projects: []` и `access: ["portal"]`, см. [contract-zone](../examples/contract-zone.ru.md#репозиторий-мобильного-приложения).

## Имя агента

`agent` — имя по умолчанию. Другому агенту в этом репозитории задают суффикс или полное имя, см. [access](access.ru.md#идентичность).

## Расположение хаба

`hub.path` — путь к локальному клону хаба; `hub.url` — адрес сервиса: поле зарезервировано для реализаций уровня 3, его смысл определяет реализация. Путь зависит от машины, поэтому переопределяется переменной окружения `DOC_HUB_PATH`; приоритет у переменной.
