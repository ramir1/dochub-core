# Протокол DocHub

Протокол — то, что обязаны соблюдать все, кто читает и пишет данные хаба: агент на уровне 1, утилита, Web, сервис. Реализация совместима, если её данные может читать и менять любая другая реализация. Уровни — [levels](../concepts/levels.ru.md).

## Что входит

| Раздел | Где |
|---|---|
| Структура хаба, синхронизация, столкновения записи | [hub-storage](hub-storage.ru.md) |
| Проекты, зоны | [projects](projects.ru.md) |
| Агенты, роли, права, видимость | [access](access.ru.md) |
| Wiki | [wiki](wiki.ru.md) |
| Внешняя документация | [docs-sources](docs-sources.ru.md) |
| Документы и ссылки | [documents](documents.ru.md) |
| Манифест репозитория | [project-manifest](project-manifest.ru.md) |
| Функции | [discussions](features/discussions.ru.md), [changes](features/changes.ru.md), [claims](features/claims.ru.md) |
| Версия формата | [versioning](versioning.ru.md) |
| Форматы файлов | [schemas/](../schemas/) |

## Что не входит

- Интерфейс команд: [cli-contract](cli-contract.ru.md) описывает эталонную реализацию `doc-hub`.
- Сетевой API, аутентификация, MCP, развёртывание: это устройство конкретной реализации.
- Значения по умолчанию эталонной реализации: срок отметки работы, число коммитов при первом просмотре, число повторов записи.

## Обязательные правила

Реализация должна:

- писать файлы строго по схемам и не терять неизвестные поля;
- не писать в хаб с неизвестным `format_version`;
- проверять роли, зоны, ограничение путями и переходы статусов, с учётом [суффикса агента](access.ru.md#суффикс);
- не менять внешнюю документацию и не добавлять её в git хаба;
- при столкновении записи не терять чужие данные, см. [hub-storage](hub-storage.ru.md#столкновения-записи).

## Определение контекста

| Что | Порядок |
|---|---|
| Хаб | Явный параметр реализации → `DOC_HUB_PATH` → `DOC_HUB_ID` → первый раздел `hubs` ближайшего вверх от текущей папки `.doc-hub.json` |
| Агент | Явный параметр → `DOC_HUB_AGENT` → `agent` раздела хаба с `DOC_HUB_AGENT_SUFFIX`; имя не определено — см. [access](access.ru.md#идентичность) |
| Проект | Явный параметр → первый в `projects` раздела хаба → первый в `access` раздела хаба → единственный проект, где агент — участник |

## Проверка данных

Проверка данных сверяет:

- **конфигурацию:** `format_version`, `repository` у источников `docs`, описаны ли агенты из владельцев и участников, допустимы ли роли;
- **обсуждения:** имя файла, обязательные поля, `uid`, статус для вида, `outcome` при статусе не `open`, `changes` и `commit` при `applied`, адресат у `note`, время UTC, метки и разделители сообщений, непустые сообщения;
- **отметки работы и просмотра:** обязательные поля, связь имени файла с агентом, время UTC;
- **wiki:** относительные ссылки ведут на существующие файлы.
