# Хранилище хаба

Хаб — git-репозиторий с конфигурацией, wiki проектов и данными функций. Подключённая внешняя документация лежит рядом, но в git не попадает. Он же — Obsidian-vault, см. [obsidian](../rules/obsidian.ru.md).

## Структура

```
<hub>/
├── README.md                    # описание хаба для людей
├── AGENTS.md                    # вход для ИИ-агентов (шаблон — templates/hub-AGENTS.ru.md)
├── .gitignore                   # .doc-hub/config.local.yaml, projects/*/docs/ (шаблон — templates/hub-gitignore)
├── .doc-hub/
│   ├── config.yaml              # проекты, зоны, агенты, роли, функции (в git)
│   └── config.local.yaml        # пути к клонам репозиториев на этой машине (не в git)
├── .obsidian/                   # настройки Obsidian
├── templates/                   # шаблоны для плагина «Шаблоны»
└── projects/
    └── <id>/
        ├── wiki/                     # своя документация, в git
        ├── docs/                     # внешняя, не в git
        │   └── <папка>/
        │       └── .source.yaml      # паспорт
        ├── discussions/
        │   └── <YYYY-MM-DD-slug>.md
        ├── changes/
        │   └── <агент>.yaml          # отметка просмотра
        └── claims/
            └── <агент>-<slug>.md     # отметка работы
```

Схемы файлов: [discussion](../schemas/discussion.ru.md), [changes](../schemas/changes.ru.md), [claim](../schemas/claim.ru.md), [docs-source](../schemas/docs-source.ru.md).

## Кто меняет какой файл

Отметки работы и просмотра разложены по файлам так, чтобы каждый файл менял только его автор. Обсуждение могут дописывать разные агенты, а wiki — править разные владельцы, см. [wiki](wiki.ru.md#одновременные-правки):

| Файл | Кто меняет |
|---|---|
| `discussions/<slug>.md` | участники дописывают сообщения; статус меняют по правилам функции |
| `changes/<агент>.yaml` | сам агент |
| `claims/<агент>-<slug>.md` | сам агент |
| `.doc-hub/config.yaml` | администратор хаба |
| `wiki/…` | владелец зоны |
| `docs/<папка>/…` | только `doc-hub docs sync`; не в git |

Отметки не конфликтуют при слиянии. Если запись в обсуждение столкнулась с чужой, CLI забирает свежую версию и дописывает сообщение заново. Человек в Obsidian разрешает такой конфликт вручную; это редкий случай.

## Синхронизация между машинами

Хаб — обычный git-репозиторий с общим удалённым репозиторием (origin). На каждой машине — свой клон.

Порядок записи для любой реализации:

1. Перед чтением и записью — `git pull --rebase`.
2. После записи — `git add` и `commit` только своих файлов. Сообщение — `<агент>: <действие> <объект>`, автор коммита — имя агента.
3. `git push`. Отказ — `pull --rebase` и повтор.

Люди в Obsidian — плагин Git (автоматический pull/push).

**Хаб без origin.** Допустимый режим для одной машины: `pull` и `push` пропускаются.

### Столкновения записи

Если `rebase` завершился конфликтом: прервать его, отменить свой коммит, обновить хаб.

- **Обсуждение:** дописать сообщение заново поверх свежей версии. Перед сменой статуса снова проверить, что переход допустим. `doc-hub` делает до трёх попыток.
- **Wiki:** отказать в записи и сообщить о конфликте, чтобы автор перечитал документ.

Чужие изменения не затираются.

Папки функций создаются при первой записи.

Сервис вместо git — реализация уровня 3, вне Core, см. [levels](../concepts/levels.ru.md).

## Существующий workspace `dochub.ws`

Сейчас в `dochub.ws` документация проектов лежит прямо в хабе (`projects/mobile-app/…`, `projects/mini-site/…`), есть папка `system/`. Рекомендации по переходу (не выполнены):

- документацию `mobile-app` и `mini-site` перенести в wiki проекта портала;
- `system/` — заменён этим Core;
- добавить `.doc-hub/config.yaml`.
