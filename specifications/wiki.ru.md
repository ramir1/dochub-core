# Wiki проекта

**Wiki** — своя документация проекта. Хаб для неё **источник истины**: файлы лежат в `projects/<id>/wiki/` и хранятся в git хаба. Обратная сторона — внешняя документация [docs](docs-sources.ru.md), которая только читается.

## Что класть в wiki

Контракты между проектами и общие описания: всё, что нужно править из одного места и читать агентам без доступа к коду. То, что меняется вместе с кодом, удобнее оставить в репозитории и подключить как docs.

## Пути

Виртуальный путь совпадает с папкой проекта: `wiki/mobile-app/09-comments.md` лежит в `projects/portal/wiki/mobile-app/09-comments.md`. Ссылка на документ — `portal:wiki/mobile-app/09-comments.md`, см. [documents](documents.ru.md).

## Кто правит

- **Человек** — прямо в Obsidian: хаб и есть хранилище. Синхронизация — плагин Git.
- **ИИ-агент** — через реализацию, а на уровне 1 — напрямую по скилу.
- Писать может только **владелец зоны** документа, а вне зон — владелец проекта. Остальные предлагают правку через `proposal`.

## Требования

Хаб предъявляет к wiki требования, см. [default-rules](../rules/default-rules.ru.md#требования-к-wiki). Ссылки сверяет проверка данных, см. [protocol](protocol.ru.md#проверка-данных). Frontmatter и `uid` пока не требуются (*предложение*).

## Одновременные правки

Один документ wiki могут править разные агенты и люди.

- Правка пишется поверх прочитанной версии. Реализация может принять коммит, с которого прочитан документ, и отклонить запись, если файл успел измениться.
- Если две машины записали один файл одновременно, вторая получает ошибку конфликта: её запись отменяется, клон хаба остаётся чистым. Документ надо прочитать заново.

## Видимость

Wiki хранится в git хаба и видна всем, у кого есть его клон: `members.<агент>.paths` проверяет только реализация. Закрыть часть wiki можно отдельным хабом или сервисом уровня 3, см. [levels](../concepts/levels.ru.md).
