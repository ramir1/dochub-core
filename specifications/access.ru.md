# Доступ: агенты, роли, зоны

## Агенты

**Агент** — участник хаба: ИИ-агент или человек. Имя уникально в хабе.

Агент в DocHub — это **роль в работе**, а не программа: одна и та же программа (Claude Code) в двух сессиях на разных зонах — два агента. Формат имени — [naming](../rules/naming.ru.md#агенты).

Агенты перечисляются в конфигурации хаба (`agents`) с описанием: человек, инструмент, назначение.

### Идентичность

Имя агента не хранится в git репозитория: в одном репозитории работают разные агенты и люди. По умолчанию оно берётся из локального манифеста, см. [project-manifest](project-manifest.ru.md).

Порядок определения (приоритет сверху вниз):

1. явный параметр реализации — полное имя;
2. переменная окружения `DOC_HUB_AGENT` — полное имя;
3. поле `agent` раздела хаба в манифесте, а если задана `DOC_HUB_AGENT_SUFFIX` — `<agent>-<суффикс>`;
4. иначе — агент не определён: записывать в хаб нельзя. Обращение без имени определяет реализация (уровни 2 и 3), пример — [cli-contract](cli-contract.ru.md). На уровне 1 имя спрашивают у человека.

Переменные удобно задавать в настройках инструмента или сессии. Если агент не знает своего имени — спросить у человека.

### Суффикс

Когда в одном проекте работают несколько агентов, им дают суффикс: `portal-tests` — это агент с именем `portal-tests`, а `portal` — его **базовый агент**. Суффикс — по шаблону `^[a-z0-9][a-z0-9-]*$`.

Регистрировать агента с суффиксом в хабе не нужно: если точной записи нет, берётся самая длинная запись `X`, для которой имя начинается с `X-`. Правило работает по самому имени, поэтому результат одинаков на всех машинах.

- **Наследуются** роль, `paths` и владение зонами и проектом.
- **Не наследуются** авторство, адресация, отметки работы и просмотра: они идут по полному имени.
- **Точная запись важнее:** зарегистрированный `portal-tests` живёт по своей записи и прав `portal` не получает. Запись — это строка в `agents` или в `members` проекта, поэтому зарегистрированный агент, которого нет в `members`, в этом проекте прав не имеет.

Правило действует для любых имён: `ramir-что-угодно` без своей записи получит права `ramir`, а опечатка в суффиксе создаст другого агента, а не ошибку.

**Аутентификация** вне Core: хаб доверяет имени.

## Роли

Роль задаётся агенту **в проекте**: `projects.<id>.members.<агент>.role`. Агент без записи в `members` доступа к проекту не имеет.

| Действие | `participant` | `reader` |
|---|:-:|:-:|
| Читать документацию (в пределах `paths`) | ✓ | ✓ |
| Читать данные функций (в пределах `paths`) | ✓ | ✓ |
| Создавать обсуждения, писать сообщения | ✓ | — |
| Ставить и снимать свои отметки работы | ✓ | — |
| Вести свою отметку просмотра изменений | ✓ | ✓ |
| Решать по предложениям (`accept` / `reject` / `apply`) | только владелец зоны | — |

## Ограничение путями

`members.<агент>.paths` — список путей документации, доступных агенту. Если не задан — доступна вся документация проекта.

```yaml
members:
  mobile-dev: { role: participant, paths: [wiki/mobile-app] }
```

Агент с ограничением видит:

- документы только в своих путях;
- обсуждения, у которых есть `refs` и все они в его путях, а также те, где он автор или адресат;
- изменения (`changes`) только по своим путям;
- отметки работы только по своим путям.

## Владельцы

Владельцы зоны (`areas.<путь>.owners`) или проекта (`owners`) — агенты, которые решают по предложениям и правят документацию в wiki. Владелец должен быть `participant` проекта.

## Политика записи

1. **Wiki** пишет только владелец зоны, вне зон — владелец проекта: агент — через реализацию или по скилу, человек — в Obsidian. **Docs** через хаб не пишется, правят в её репозитории.
2. **Данные функций** — в пределах прав роли, по файлам — [hub-storage](hub-storage.ru.md#кто-меняет-какой-файл).
3. **Конфигурация хаба** — администратор хаба (человек с правом записи в репозиторий хаба). Отдельной роли администратора в модели нет.

## Соблюдение прав

На уровне 1 права держатся на правилах и скиле, на уровне 2 их проверяет реализация. Настоящее разграничение возможно только на уровне 3, см. [levels](../concepts/levels.ru.md). Агент, которому нельзя видеть чужой код, не должен получать клон этого репозитория.
