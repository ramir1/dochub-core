# Доступ: агенты, роли, зоны

## Агенты

**Агент** — участник хаба: ИИ-агент или человек. Имя уникально в хабе (`^[a-z0-9][a-z0-9-]*$`).

Агент в DocHub — это **роль в работе**, а не программа: одна и та же программа (Claude Code) в двух сессиях на разных зонах — два агента. Рекомендуемое имя — `<человек>-<инструмент>-<зона>`, например `ramir-claude-backend`, `ramir-codex-frontend`; для человека — его имя (`ramir`). См. [naming](../rules/naming.ru.md#агенты).

Агенты перечисляются в конфигурации хаба (`agents`) с описанием: человек, инструмент, назначение.

### Идентичность

Имя агента задаётся **в окружении агента, а не в репозитории**: в одном репозитории работают несколько агентов.

Порядок определения (приоритет сверху вниз):

1. явный параметр реализации;
2. переменная окружения `DOC_HUB_AGENT`;
3. иначе — агент не определён: записывать в хаб нельзя. Обращение без имени определяет реализация (уровни 2 и 3), пример — [cli-contract](cli-contract.ru.md). На уровне 1 имя спрашивают у человека.

Переменную удобно задавать в настройках инструмента или сессии (например, в переменных окружения, которые инструмент передаёт агенту). Если агент не знает своего имени — спросить у человека.

**Аутентификация** вне Core: хаб доверяет имени.

## Роли

Роль задаётся агенту **в проекте**: `projects.<id>.members.<агент>.role`. Агент без записи в `members` доступа к проекту не имеет.

| Действие | `participant` | `reader` |
|---|:-:|:-:|
| Читать документацию (в пределах `paths`) | ✓ | ✓ |
| Читать данные функций (в пределах `paths`) | ✓ | ✓ |
| Создавать обсуждения, писать сообщения | ✓ | — |
| Ставить и снимать свои отметки работы | ✓ | — |
| Вести свою отметку просмотра изменений | ✓ | ✓ |
| Решать по предложениям (`accept` / `reject` / `apply`) | только владелец зоны | — |

## Ограничение путями

`members.<агент>.paths` — список путей документации, доступных агенту. Если не задан — доступна вся документация проекта.

```yaml
members:
  mobile-dev: { role: participant, paths: [wiki/mobile-app] }
```

Агент с ограничением видит:

- документы только в своих путях;
- обсуждения, у которых есть `refs` и все они в его путях, а также те, где он автор или адресат;
- изменения (`changes`) только по своим путям;
- отметки работы только по своим путям.

## Владельцы

Владельцы зоны (`areas.<путь>.owners`) или проекта (`owners`) — агенты, которые решают по предложениям и правят документацию в wiki. Владелец должен быть `participant` проекта.

## Политика записи

1. **Wiki** пишет только владелец зоны, вне зон — владелец проекта: агент — через реализацию или по скилу, человек — в Obsidian. **Docs** через хаб не пишется, правят в её репозитории.
2. **Данные функций** — в хабе, в пределах прав роли; каждый файл пишет его автор (исключения — в спецификации функции).
3. **Конфигурация хаба** — администратор хаба (человек с правом записи в репозиторий хаба). Отдельной роли администратора в модели нет.

## Соблюдение прав

На уровне 1 права держатся на правилах и скиле. На уровне 2 их проверяет реализация: команды работают только в пределах прав. Это защита от ошибок, а не от намеренного обхода: хаб доверяет имени агента, а у того, у кого есть клон хаба или репозитория, файлы доступны напрямую. Настоящее разграничение возможно только на уровне 3, см. [levels](../concepts/levels.ru.md). Агент, которому нельзя видеть чужой код, не должен получать клон этого репозитория.
