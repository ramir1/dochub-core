# Работа через Obsidian

Obsidian — интерфейс хаба для людей: хаб открывается как vault, один на все проекты. В нём видны и правятся wiki, видны обсуждения, отметки работы, карточки доски и внешняя документация. Это способ для уровней 1 и 2 — без утилиты или без веб-интерфейса, см. [уровни](../concepts/levels.ru.md). На уровне 3 файлов хаба на машине нет, люди работают через сервис.

## Что можно делать в Obsidian

Obsidian не знает правил хаба: права, зоны и связи никто не проверяет, а `.doc-hub/`, `.source.yaml` и `changes/` в нём не видны. Та же памятка лежит в корне хаба на двух языках: `OBSIDIAN.md` и `OBSIDIAN.ru.md`.

| Действие | Можно в Obsidian | Что будет | Как правильно |
|---|---|---|---|
| Читать wiki, docs, обсуждения | Да | — | — |
| Править текст в `wiki/` | Да, в своей зоне | Плагин Git отправит правку | — |
| Переименовать файл или папку в `wiki/` | С осторожностью | Ссылки внутри wiki обновятся, но зоны и пути агентов в конфигурации перестанут совпадать, а ссылки из обсуждений устареют | Потом поправить `.doc-hub/config.yaml` |
| Править файл в `docs/` | Нет | Правка пропадёт при следующей выгрузке | Править в источнике |
| Переименовать папку в `docs/` | Нет | Папка станет лишней, а выгрузка создаст прежнюю заново | Отключить источник и подключить его под новым именем |
| Дописать сообщение в обсуждение | Да, по формату | — | См. [Обсуждения](#обсуждения) |
| Сменить статус обсуждения | Вручную | Нужно поправить frontmatter и добавить метку; переход никто не проверит | Лучше через реализацию |
| Переименовать файл обсуждения | Нет | Старое имя перестанет работать | Не переименовывать |
| Менять `.doc-hub/`, `.source.yaml`, `changes/` | Не видны | — | Администратор хаба, в обычном редакторе |

После ручных правок запустите проверку данных, см. [protocol](../specifications/protocol.ru.md#проверка-данных). Она находит ошибки формата и битые ссылки в wiki, но не находит лишние папки в `docs/` и зоны без файлов.

## Настройка vault

1. Клонировать хаб: `git clone <origin хаба> ~/projects/hub`. Открыть папку в Obsidian: «Открыть папку как хранилище».
2. **Файлы и ссылки:**
   - «Автоматически обновлять внутренние ссылки» — вкл.;
   - «Использовать [[Wiki-ссылки]]» — **выкл.**;
   - «Формат новых ссылок» — относительный путь.
3. **Основные плагины:** «Шаблоны» (папка — `templates`), «Свойства», «Поиск», «Обратные ссылки».
4. **Сторонние плагины:**
   - **Git** (obsidian-git) — автоматический pull при открытии и push после изменений; сообщение коммита — с именем человека-агента (`ramir: …`);
   - **Note UID Generator** — для `uid` обсуждений, см. ниже.

## Note UID Generator

Файлы хаба пишут разные авторы на разных машинах. Автоматическая генерация `uid` изменила бы чужой файл при открытии, поэтому она **выключена**; `uid` ставится вручную командой плагина в своём новом файле обсуждения.

| Ключ (`.obsidian/plugins/note_uid_generator/data.json`) | Значение |
|---|---|
| `uidKey` | `uid` |
| `uidGenerator` | `ulid` |
| `autoGenerateUid` | `false` |
| `duplicateUidCheck` | `notify` |

## Wiki

Своя документация — `projects/<id>/wiki/`. Правьте прямо в Obsidian, плагин Git отправит изменения. Правьте документы своей зоны, требования — [default-rules](default-rules.ru.md#требования-к-wiki). Другая машина могла изменить тот же файл: при конфликте плагин Git покажет его, разрешается как обычный конфликт git.

## Внешняя документация

`projects/<id>/docs/<папка>/` — только чтение, см. [docs-sources](../specifications/docs-sources.ru.md).

- **Обновить** — операцией выгрузки в реализации, см. [docs-sources](../specifications/docs-sources.ru.md#обновление).
- **Не редактировать.** Правка пропадёт при следующем обновлении и в репозиторий не попадёт. Папка в `.gitignore` хаба, плагин Git её не отправляет.
- **Свежесть.** Коммит — в `.source.yaml`. В Obsidian этот файл скрыт (имя с точкой): смотрите его вне Obsidian или через реализацию.
- **Поиск:** `path:"projects/portal/wiki"` или `path:"projects/portal/docs"`.

## Обсуждения

- **Читать:** `projects/<id>/discussions/<файл>.md` — весь разговор в одном документе.
- **Открытые обсуждения:** поиск `path:"projects/portal/discussions" [status:open]`.
- **Мои входящие:** поиск `[to:ramir]`.
- **Создать:** новый файл `YYYY-MM-DD-slug.md` из шаблона `templates/discussion.md`, команда плагина «сгенерировать UID».
- **Ответить:** дописать в конец файла пустую строку, разделитель `---`, метку `[YYYY-MM-DDTHH:MM:SSZ <агент>]` и текст. Чужие сообщения не менять.
- Время в шаблонах — местное, а схема требует UTC: при создании заменить его на время UTC. Это неудобство этапа 1.

## Отметки работы

`projects/<id>/claims/` — кто над чем работает. Человек тоже может поставить отметку из шаблона `templates/claim.md`. В шаблоне `created` и `expires` совпадают: перевести время в UTC и указать срок в `expires`, иначе отметка сразу истечёт.

## Доска

`projects/<id>/board/` — карточки задач. Создать карточку можно из шаблона `templates/card.md`, команда плагина «сгенерировать UID». Время заменить на UTC.

Колонками карточки показывает встроенный вид [Kanban в Bases](https://obsidian.md/help/bases/views/kanban) (Obsidian 1.14 и новее): папка `projects/<id>/board`, группировка по свойству `status`. Перетаскивание записывает новое значение `status` в заметку. Сведения взяты из документации, на практике вид не проверялся.

Ограничения:

- **Правила не проверяются.** Перетаскивание меняет только `status`: строку истории, `assignee` и `outcome` человек дописывает сам, а переходы и права Obsidian не сверяет. Такие правки находит проверка данных.
- **Новые колонки.** По описанию плагина Kanban to Bases, вид показывает только колонки, перечисленные в базе. Список статусов фиксирован, поэтому достаточно перечислить их один раз.
- **Неизвестно:** как файл `.base` ведёт себя в git хаба при правках с разных машин.

Плагин [obsidian-kanban](https://github.com/mgmeyers/obsidian-kanban) не подходит: он хранит всю доску в одном файле, а карточка хаба — отдельный файл.
