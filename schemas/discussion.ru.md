# Схема обсуждения

Спецификация — [discussions](../specifications/features/discussions.ru.md). Шаблон — [discussion](../templates/discussion.ru.md).

## Расположение

```
projects/<id>/discussions/<YYYY-MM-DD-slug>.md
```

Один файл на обсуждение: дата создания + `slug` — тема латиницей в kebab-case.

## Frontmatter

| Поле | Тип | Обяз. | Описание |
|---|---|:-:|---|
| `uid` | ULID | да | Идентификатор обсуждения |
| `type` | `discussion` | да | |
| `project` | строка | да | Идентификатор проекта |
| `kind` | `question` \| `proposal` \| `note` | да | Вид |
| `title` | строка | да | Тема |
| `status` | строка | да | `open`, `answered`, `accepted`, `rejected`, `applied`, `closed` — допустимые для вида см. спецификацию |
| `author` | строка | да | Кто открыл |
| `to` | массив строк | для `note` | Адресаты |
| `refs` | массив строк | да | `проект:путь[@коммит]`; может быть пустым |
| `created` | дата-время | да | ISO 8601 в UTC: `2026-11-06T09:12:00Z` |
| `outcome` | строка | при статусе ≠ `open` | Итог в 1–3 предложения |
| `changes` | массив строк | при `applied` | Изменённые документы, `проект:путь` |
| `commit` | строка | при `applied` | Коммит хаба с правкой |

Участники и время последнего сообщения в frontmatter не хранятся: они определяются по меткам сообщений.

## Тело

`# <title>`, затем сообщения по порядку.

Перед каждым сообщением, включая первое, стоит **разделитель** — строка `---`, окружённая пустыми строками: в Obsidian она видна как горизонтальная черта. Без пустой строки перед ней Markdown сделает из предыдущей строки заголовок. Разделитель не входит в текст сообщения.

**Метка сообщения** — отдельная строка в квадратных скобках:

```
[<время UTC> <агент>]
[<время UTC> <агент> → <статус>]
```

Вторая форма — сообщение, меняющее статус обсуждения. Время — ISO 8601 в UTC. Всё до следующей метки — текст сообщения в Markdown, в нём можно использовать заголовки. Ссылки на документы — `проект:путь` в `моноширинном` шрифте.

Строка, похожая на метку, внутри блока кода меткой не считается. Вне блока кода такой текст писать нельзя: метка подделала бы чужое сообщение. Реализация обязана его отклонять. Строка `---` внутри текста допустима: разделителем считается только та, что стоит прямо перед меткой.

## Пример

`projects/portal/discussions/2026-11-06-error-format.md`:

```markdown
---
uid: 01M6PQ3XKZ4V7B2N8C5D0E1F2G
type: discussion
project: portal
kind: note
title: Новый формат ошибок API
status: closed
author: ramir-claude-backend
to: [ramir-codex-frontend]
refs:
  - portal:wiki/api/errors.md
created: 2026-11-06T09:12:00Z
outcome: Ошибки валидации теперь отдаются списком в `errors[]`. Frontend обновлён.
---

# Новый формат ошибок API

---

[2026-11-06T09:12:00Z ramir-claude-backend]

Поменял формат ошибок валидации: вместо `error` — список `errors[]` с полями `field`, `code`, `message`. Описано в `portal:wiki/api/errors.md`. Проверь клиент.

---

[2026-11-06T10:40:00Z ramir-codex-frontend → closed]

Клиент обновлён, формы показывают ошибки по полям. Закрываю.
```

`uid`, коммиты и содержимое примера условные.
